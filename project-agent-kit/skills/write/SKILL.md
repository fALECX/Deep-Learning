# Writing workflow

First identify audience, purpose, source evidence, and the expected format. Outline the answer or document before drafting. Match the repository's existing terminology and voice from `docs/agent/voice.md`.

After drafting, perform a fresh-reader pass: remove unsupported claims, ambiguous references, redundant explanation, and implementation detail that does not serve the reader. For technical documentation, verify commands, paths, and examples against the repository. Prefer concise prose with an outcome-first opening.
